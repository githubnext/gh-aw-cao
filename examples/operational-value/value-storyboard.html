Goal and eligible population
Keep production files small without changing behavior. Count non-test Go files anywhere under pkg/, including newly added, moved, and replacement files.
Fixed evaluator
One count per file with at least 800 lines. Unit: oversized files. Direction: lower is better. The definition and evaluator version are reviewed before interpreting results.
Optional integration measurement
Follow verified proposal-to-implementation links and measure a verified before/after integration boundary. The illustrated squash merge uses its actual first parent, not its original proposal base. A multi-commit rebase requires the whole landed range. A shared integration is counted once, not credited in full to every linked PR. Unknown boundaries remain unknown. Keep zero and negative changes.
Independent repository measurement
Sample at a declared cadence regardless of acceptance, including changes by other contributors. The example compares day 7 with the displayed day 1 snapshot, not a pre-adoption baseline or a causal impact estimate.
No universal acceptance state
Native delivery, domain lifecycle, readiness to measure, and outcome are different facts. Comments and no-ops do not automatically create acceptance watches. A declared downstream question creates a watch only when it defines observable evidence. No observable outcome does not mean success.
Small deterministic collection loop
Verified admission → due/dirty plan → needed evidence → cached evaluation → atomic publication → acknowledge the captured generation. Stop before collector startup if nothing is due or dirty. Newer invalidations remain queued. Overflow means bounded scope reconciliation, never silently dropped changes.
Selective computation
Establish a bounded baseline. Fold changed trees using cached child aggregates; skip proven unchanged subtrees. Key reuse by evaluator, frozen recipe, path context, and immutable object identity. Measure identical content once but count every eligible occurrence. New objects and links invalidate discovery dependencies. Incomplete coverage remains explicit; a hash is not evidence of freshness.
Independent clocks and dormant waits
A lifecycle update cannot postpone the repository cadence or another question's maturity deadline. Missing samples stay visible and can be repaired later without moving newer checkpoints. Keep compact watches while humans decide; retire polling after an immutable question is answered. Reconciliation remains necessary for missed events. Elapsed time is not proof of durable benefit or preserved behavior.
Tracker-driven acquisition
A workflow tracker correlates outputs; it is not a unique output identity, an event subscription, or proof of origin. Map trusted receipts to repository and GitHub object IDs, consume authenticated lifecycle events, deduplicate deliveries, and fetch only missing dependent evidence. Keep bounded reconciliation for missed or ambiguous events.
Evidence and limits
The diagram numbers are fictional; the separate operation-count study is generated by a synthetic executable model. Neither establishes unchanged behavior. The model assumes verified input facts and does not implement GitHub admission, a real Git parser, distributed leases, production storage, or enterprise access controls.
Forward-looking results
Distinguish known next-measurement deadlines, statistical forecasts of repository outcomes, and conditional what-if scenarios. Fit only on evidence available at the historical forecast origin. For acceptance-time forecasts, retain pending cases as censored observations and handle rejections separately. Keep uncertainty, forecast horizon, model version, and the comparison with a simple baseline visible. Sparse evidence may support scenarios but no reliable forecast.
Event, capture, and availability
Record when an outcome occurred, when evidence was captured, and when that assessment first became available. Late publication cannot make a fact visible in an earlier historical forecast. A retry keeps the original capture time; it does not invent freshness. Preserve immutable facts and keep new or corrected assessment versions distinct.
Enterprise replay and retention
Retain the actual replay inputs, not only their hashes or mutable URLs. Pin the reviewed contract, evaluator dependencies, environment, and original cutoffs. Reproduce the assessment without live evidence replacement or side effects, under current access controls. Archive reachability and retention must survive cache reuse. Pruning canonical history requires an explicit versioned coverage/retention contract; this prototype does not change CAO's current packets.
Keep gh-aw and CAO responsibilities separate
gh-aw owns workflow intent, execution, safe-output delivery, native queues, per-run grading, and its replay mechanisms. The proposed CAO role is later repository observations and optional linked-integration diagnostics. A production design would reuse CAO's existing admission, queue, collector, caches, and atomic publication; this reference is not wired into them. Do not add an agent campaign, competing grader, or another runtime for deterministic collection.

Research: prior art, optimization, and limits

Assessment: these are established techniques, not a demonstrated new algorithm. The potential differentiation is a governed integration of reviewed intent, GitHub relationships, Git's immutable content graph, deterministic observations, point-in-time forecasts, and reproducible evidence. Primary sources support the design below; this is not an exhaustive commercial or patent novelty search.

Goals to measurements
Google HEART already provides a process for mapping product goals to metrics. AI-assisted contract authoring is a way to apply that discipline, not proof of a new measurement theory.
Objects, events, and lifecycle
OCEL 2.0 models events, object identities, changing attributes, and qualified relationships. This is relevant prior art for linking workflows, outputs, implementations, and evidence without conflating their identities.
Compute deltas, not history
DBSP (2022) formalizes incremental view maintenance. Apache Beam separates event timestamps, windows, watermarks, triggers, state, and timers. Borrow the correctness rules; a small collector does not need a new distributed stream platform.
Git-native reuse and correct boundaries
Git objects provide content-addressed trees and blobs, enabling subtree reuse when evaluator context is unchanged. GitHub's pull request API documents different meanings of merge_commit_sha for merge, squash, and rebase. The final commit's first parent is not a universal whole-PR baseline.
Selective evaluation already exists
LangSmith online evaluation supports filters, sampling, and conditional triggers. Our proposed distinction is measuring externally accepted repository outcomes with a frozen deterministic rule, not merely attaching a subjective score to a trace.
Event-driven API savings
GitHub webhook guidance covers narrow subscriptions, secrets, event/action checks, and delivery IDs. Failed deliveries are not automatically redelivered, so push-based collection still needs recovery and reconciliation.
Forecasting is a separate inference
Predictive process monitoring (2016/2017) already uses event logs to predict running cases and remaining time. Forecasting: Principles and Practice explains rolling-origin evaluation and comparisons with simple benchmarks. This does not justify fitting a model to the four fictional points here.
Replay and provenance
Event Sourcing (2005) describes reconstruction, historical queries, captured external responses, and disabling external updates during replay. SLSA provenance provides a model for recording build identity, inputs, dependencies, and outputs. Neither alone certifies this design as secure or compliant.
Association is not causal impact
Google CausalImpact explicitly requires assumptions about unaffected controls and stable relationships. A before/after difference or an ordinary forecast is not, by itself, a causal estimate of agent value.
