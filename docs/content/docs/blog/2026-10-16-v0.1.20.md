CAO [v0.1.20](https://github.com/githubnext/gh-aw-cao/releases/tag/v0.1.20) is a pre-release, not a stable release. The comparison from v0.1.19 lists 73 commits. This post covers the changes whose behavior I could confirm in the repository files at the release tag; it leaves out the rest, including routine logging and refactoring commits.

## Commands run through a durable queue

Local admin and trusted canvas sessions now share one durable first-in, first-out command queue. [`dashboard/README.md`](https://github.com/githubnext/gh-aw-cao/blob/v0.1.20/dashboard/README.md) describes the behavior: approval covers only the exact queued invocation, queued commands survive a restart, and an interrupted command is recorded as failed instead of being silently repeated. After an interrupted run, the queue pauses until you restart the local server with `--acknowledge-command-recovery`.

The dashboard gained a Commands page backed by this queue ([#18189](https://github.com/githubnext/gh-aw-cao/pull/18189)). Later changes queue bulk updates as individual commands ([#18223](https://github.com/githubnext/gh-aw-cao/pull/18223)) and make command output a persistent full-page console ([#18251](https://github.com/githubnext/gh-aw-cao/pull/18251)). I did not run these flows end to end, so treat the README as the description of intended behavior.

## Activity collection that degrades gracefully

Several changes make the Activity workflow less likely to fail on a single bad input or limit:

- Expired Activity shards are recycled and cache growth is bounded ([#18157](https://github.com/githubnext/gh-aw-cao/pull/18157)). [`activity/README.md`](https://github.com/githubnext/gh-aw-cao/blob/v0.1.20/activity/README.md) documents the `force-recycle` and `recycle-only` dispatch inputs for maintenance passes.
- An invalid unified session artifact is now skipped with a warning instead of aborting collection (`activity/session-evidence.mjs`, [#18203](https://github.com/githubnext/gh-aw-cao/pull/18203)).
- Log downloads are capped at 10 minutes by default through `REPORT_LOG_TIMEOUT` in `activity/collect-logs.sh` ([#18204](https://github.com/githubnext/gh-aw-cao/pull/18204)).
- Partial Activity snapshots are preserved under GitHub API limits ([#18197](https://github.com/githubnext/gh-aw-cao/pull/18197)).

If you run Activity on a schedule, expect fewer all-or-nothing failures. I did not measure how often failures occurred before this release.

## Dashboard navigation

The dashboard Updates page is split into Repositories and Campaigns tabs ([#18149](https://github.com/githubnext/gh-aw-cao/pull/18149)), and Operational Value moves into the Data navigation ([#18144](https://github.com/githubnext/gh-aw-cao/pull/18144)). Both changes appear in the dashboard definitions under `dashboard/site/dashboard-fragments/`. I confirmed the changed files but did not review the rendered pages.

## Minimum gh-aw version

The root `aw.yml` now declares `min-version: v0.92.3` ([#18276](https://github.com/githubnext/gh-aw-cao/pull/18276)). Update your `gh aw` extension before you add or update the campaign.

## What to do next

Because this is a pre-release, try it in a non-production control repository first. Upgrade `gh aw` to v0.92.3 or later, then read the [v0.1.20 release page](https://github.com/githubnext/gh-aw-cao/releases/tag/v0.1.20). If you use the local admin CLI, review the command queue section of the dashboard README before enabling queued commands. The evidence reviewed doesn't show changes to control-plane policy or rollout defaults.
