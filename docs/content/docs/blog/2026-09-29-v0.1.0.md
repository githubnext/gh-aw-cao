CAO [v0.1.0](https://github.com/githubnext/gh-aw-cao/releases/tag/untagged-33f072f614110dfcdda5) is out. This is a full release, not a pre-release. It expands the dashboard's read-only surfaces, hardens multi-tenant authentication, adds an optional webhook-driven ingestion path for hosted servers, and tightens a safety gap in worker dispatch.

## A safety fix you should know about if you run workers

The most consequential change in this release is a breaking one: orchestrators must now pass an explicit `safe_output_mode` on every worker dispatch call. Implicit or default dispatch is no longer accepted.

This closes a real gap. PR [#14711](https://github.com/githubnext/gh-aw-cao/pull/14711) documents a SelfCare run that omitted `safe_output_mode` from all 11 worker dispatches in a run; the workers silently fell back to `review` even though policy had resolved the target repository to `live`, so the intended live-only setup work was skipped without any error. The fix requires all 47 worker workflow dispatch contracts to declare a mode explicitly, so an omitted mode now fails validation instead of quietly defaulting. If you maintain custom orchestrator or dispatch logic against this control plane, check that every dispatch call sets `safe_output_mode` explicitly.

## New read-only surfaces: Marketplace and Memory browser

The dashboard gains a new [Marketplace](https://github.com/githubnext/gh-aw-cao/pull/14170) campaign package, styled to match [github.com/marketplace](https://github.com/githubnext/gh-aw-cao/pull/14231), with responsive card grids ([#14583](https://github.com/githubnext/gh-aw-cao/pull/14583)), a richer package detail view ([#14540](https://github.com/githubnext/gh-aw-cao/pull/14540)), duplicate-entry prevention ([#14593](https://github.com/githubnext/gh-aw-cao/pull/14593)), and improved detail links and contrast ([#14611](https://github.com/githubnext/gh-aw-cao/pull/14611)).

Alongside it, a full-screen, collapsible campaign repository-memory browser landed in [#14081](https://github.com/githubnext/gh-aw-cao/pull/14081) and [#14212](https://github.com/githubnext/gh-aw-cao/pull/14212), with mobile-browsing improvements ([#14237](https://github.com/githubnext/gh-aw-cao/pull/14237)) and navigation polish ([#14312](https://github.com/githubnext/gh-aw-cao/pull/14312)). The underlying code — `activity/repository-memory.mjs`, the `campaign-memory` dashboard component, and the `repositorymemory` server package — is in the repository at the release tag, so this is a real, shippable surface rather than a partial branch.

## Authentication now covers GitHub Enterprise and separates read/write credentials

A cluster of changes hardens how CAO authenticates across tenants: support for enterprise hosts and GHE data residency ([#14046](https://github.com/githubnext/gh-aw-cao/pull/14046), [#14047](https://github.com/githubnext/gh-aw-cao/pull/14047)), separated read and write PAT credentials ([#14057](https://github.com/githubnext/gh-aw-cao/pull/14057)), scope-first setup with owner-routed PATs ([#14353](https://github.com/githubnext/gh-aw-cao/pull/14353)), a more resumable PAT setup flow ([#14672](https://github.com/githubnext/gh-aw-cao/pull/14672)), and centralized worker target authentication ([#14744](https://github.com/githubnext/gh-aw-cao/pull/14744)). A related fix restores GHE App installation discovery ([#14065](https://github.com/githubnext/gh-aw-cao/pull/14065)).

Two security-relevant fixes are also in this release: preventing public controls from reaching non-public repositories ([#14454](https://github.com/githubnext/gh-aw-cao/pull/14454)) and scoping the safe-outputs write App token to only the admitted target repository ([#14818](https://github.com/githubnext/gh-aw-cao/pull/14818)).

## An optional path for hosted servers: webhook-driven ingestion

Hosted CAO server deployments can now acquire evidence through a GitHub App using webhook delivery instead of the scheduled Actions sweep. The release documents this as an alternative profile, not an addition — a deployment picks exactly one ingestion profile, and running both is a startup error. The collector reuses the existing log-acquisition, compaction, and canonical-ingest code paths and writes to a byte-compatible evidence store, so downstream projection logic doesn't change. The design is recorded in `adr/server-webhook-driven-ingestion.md` and `specs/server-ingestion.md`, both present at this release tag. Supporting hardening includes durable at-least-once webhook processing ([#14634](https://github.com/githubnext/gh-aw-cao/pull/14634)) and an ingestion reliability simulator with health visibility ([#14632](https://github.com/githubnext/gh-aw-cao/pull/14632)).

If you run the default Actions-only setup, this change doesn't affect you — it's additive and opt-in for hosted deployments.

## More deployment options and cost visibility

New deployment profiles landed for Coolify ([#14161](https://github.com/githubnext/gh-aw-cao/pull/14161), plus a sample Compose generator in [#14527](https://github.com/githubnext/gh-aw-cao/pull/14527)), Railway ([#14542](https://github.com/githubnext/gh-aw-cao/pull/14542)), and Upstash Redis ([#14205](https://github.com/githubnext/gh-aw-cao/pull/14205)), along with optional OpenTelemetry server metrics ([#14443](https://github.com/githubnext/gh-aw-cao/pull/14443)).

On the cost and operational-value side, the Cost page gains a "Cost per workflow run" horizontal-bar chart, declared in the dashboard's Dashboard Language fragment rather than hand-written JavaScript ([#14608](https://github.com/githubnext/gh-aw-cao/pull/14608)). The experimental Operational Value page was also restructured ([#14609](https://github.com/githubnext/gh-aw-cao/pull/14609)), and the Go collector reconstructs operational-value history more accurately ([#14520](https://github.com/githubnext/gh-aw-cao/pull/14520)).

## What to do next

If you operate a control-plane repository, review any custom orchestrator code or workflow dispatch calls and confirm `safe_output_mode` is always set explicitly — the new validation will reject dispatches that omit it. If you run a hosted CAO server, webhook-driven ingestion is optional; the default Actions sweep continues to work unchanged. Read the full [release notes](https://github.com/githubnext/gh-aw-cao/releases/tag/untagged-33f072f614110dfcdda5) for the complete list of fixes and documentation updates included in this release.
