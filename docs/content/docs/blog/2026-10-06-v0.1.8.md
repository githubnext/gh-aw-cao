CAO [v0.1.8](https://github.com/githubnext/gh-aw-cao/releases/tag/v0.1.8) is out as a pre-release. It's a small, fix-focused release: a dashboard layout bug, a more reliable npm install path, and two internal refactors that make existing logging and state-handling code easier to test.

## Dashboard help tooltips no longer cover action buttons

On view pages like the campaign dashboard, each section heading carries a small help tooltip icon next to its title. Previously that icon was positioned absolutely in the top-right corner of the section, which meant it could land on top of action buttons such as "Update all" and "Upgrade all" at desktop and mobile widths. [#16516](https://github.com/githubnext/gh-aw-cao/pull/16516) moves the tooltip into normal document flow — it now renders before the section's content instead of being pinned over it, with CSS changed from `position: absolute` to `width: fit-content; margin: 0 0 8px auto`. If you maintain custom dashboard views and were adjusting layout around this overlap, you shouldn't need to anymore.

## A steadier npm install path

[#16499](https://github.com/githubnext/gh-aw-cao/pull/16499) replaces the `source-map-js` registry dependency with a small local adapter, so installs no longer fail when that package is unavailable from a configured npm feed. Source-map behavior for PostCSS and CSS-tree is preserved. The Docker dashboard build also drops the Vitest dependency tree it previously pulled in, trimming what gets installed for a production build.

## Internal cleanups: quota telemetry and benchmark-flag validation

Two refactors extract inline logic into pure, independently testable functions with added diagnostic logging, continuing a pattern already used elsewhere in the server code:

- [#16515](https://github.com/githubnext/gh-aw-cao/pull/16515) pulls the GitHub quota operation's outcome classification — mapping a declared outcome and terminal error to a span outcome, status, and optional attributes — into a standalone `classifyOperationFinish` function in `server/internal/githubquota/telemetry.go`, with new table-driven tests and a dedicated `cao:githubquota:telemetry` logger.
- [#16508](https://github.com/githubnext/gh-aw-cao/pull/16508) does the same for the dashboard benchmark-queries CLI, extracting the `--source`/`--candidates` required-flag check into a `validateBenchmarkFlags` function in `server/cmd/cao-dashboard/benchmark_queries.go` that logs which flag was missing without exposing the operator-supplied paths.

Neither change affects externally visible behavior; both are about making existing validation and telemetry logic verifiable in isolation.

There's also a reactive-state cleanup in [#16511](https://github.com/githubnext/gh-aw-cao/pull/16511): the dashboard's table-region component (`dashboard/site/src/components/table-region.js`) now owns its result-count text and "more" button visibility through reactive state rather than direct DOM writes, matching the pattern used elsewhere in the dashboard's view components.

## What to do next

Control-plane operators don't need to do anything for this release — all four changes are fixes or internal refactors with no configuration or behavior changes to adopt. If you run a self-hosted npm install for the dashboard build and previously worked around `source-map-js` registry failures, you can drop that workaround. Read the full [release notes](https://github.com/githubnext/gh-aw-cao/releases/tag/v0.1.8) for the complete change list, including [#16508](https://github.com/githubnext/gh-aw-cao/pull/16508), [#16511](https://github.com/githubnext/gh-aw-cao/pull/16511), [#16515](https://github.com/githubnext/gh-aw-cao/pull/16515), and [#16516](https://github.com/githubnext/gh-aw-cao/pull/16516).
