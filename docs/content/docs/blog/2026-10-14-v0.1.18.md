CAO [v0.1.18](https://github.com/githubnext/gh-aw-cao/releases/tag/v0.1.18) is a stable release, not a pre-release. Its only commit changes how the private Release workflow orders its steps, so the notes you read on a release are added after the tag is already published and immutable.

## Publish first, then write the notes

Before this release, the workflow added release highlights to the draft and then published it. [#17945](https://github.com/githubnext/gh-aw-cao/pull/17945) (commit `a93bcd762`) reverses that order. In `.github/workflows/release.md`, the "Publish verified prerelease" job now publishes the verified draft as an immutable prerelease under the exact `vX.Y.Z` tag. The job checks that the published release is not a draft, is marked as a prerelease, and is immutable. Only after that does the highlights agent update the release description.

The PR description says the reason is that editing notes on a draft could trigger GitHub's untagged placeholder behavior. The workflow now instructs the agent that its only write is the release-description update, and that it must not create, publish, promote, or otherwise change the release state.

## What this means for failures

[`docs/operations.md`](https://github.com/githubnext/gh-aw-cao/blob/v0.1.18/docs/operations.md) now describes two failure modes. A failure before publication leaves the draft unpublished. A failure after publication leaves a correctly tagged prerelease for diagnosis, and never a stable release that quickstart or update can select.

Maintainers still finish the process by hand: review the generated notes, confirm the tag targets the intended `main` commit, confirm both runtime assets are present, then remove the prerelease designation and mark the release as latest.

## Not covered here

The published release notes also credit a quickstart fix for malformed latest-release tags ([#17933](https://github.com/githubnext/gh-aw-cao/pull/17933)). That commit is already contained in `v0.1.17`, and the comparison from `v0.1.17` to `v0.1.18` contains only #17945, so this post does not describe it as a change in this release.

## What to do next

If you install or update CAO with `gh aw add` or `gh aw update`, you don't need to change anything for this release. If you maintain the release process, review the updated release section in `docs/operations.md` and the [v0.1.18 release page](https://github.com/githubnext/gh-aw-cao/releases/tag/v0.1.18). The evidence here doesn't show any change to runtime or dashboard behavior.
