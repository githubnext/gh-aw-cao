CAO [v0.1.21](https://github.com/githubnext/gh-aw-cao/releases/tag/v0.1.21) is a pre-release, not a stable release. The comparison from v0.1.20 lists 50 commits. This post covers the changes whose behavior I could confirm in the repository files at the release tag. It leaves out routine debug-logging and refactoring commits, and anything I could not verify.

## A `gh cao` extension for operators

This release adds a Go-based GitHub CLI extension. The first change scaffolds the extension and builds versioned release binaries ([#18515](https://github.com/githubnext/gh-aw-cao/pull/18515)); the second adds operator commands and campaign controls ([#18528](https://github.com/githubnext/gh-aw-cao/pull/18528)). The [CAO Commands reference](https://github.com/githubnext/gh-aw-cao/blob/v0.1.21/docs/cao-cli.md) describes the result.

Policy and workflow controls (`init`, `campaigns mode`, `campaigns enable`, `campaigns disable`) run natively in Go and need no Node runtime. Most other commands, such as `setup`, `add`, `update`, `validate`, and the read-only analysis commands, still call the installed CAO Node runtime, which requires Node.js 24 or later. The reference states plainly that the extension is not yet a Node-free replacement.

Two details matter if you already script against `./cao.sh`:

- The wrapper keeps its existing syntax, including `./cao.sh mode`, `enable`, and `disable`.
- `gh cao doctor` is not the same as `./cao.sh doctor`. The extension checks only the local `gh` executable, while the wrapper command checks and repairs the SQLite snapshot.

There is no `gh cao run`. Starting workflows still belongs to gh-aw. The release workflow now also builds versioned extension binaries and verifies their reported version before publishing ([`.github/workflows/release.md`](https://github.com/githubnext/gh-aw-cao/blob/v0.1.21/.github/workflows/release.md)).

## Safer static serving and markup extraction

A security fix ([#18399](https://github.com/githubnext/gh-aw-cao/pull/18399)) changes `server/internal/server/server.go` and adds regression tests in `server/internal/server/static_security_test.go`. Per the pull request description, it confines static reads to the site root, escapes access-token bootstrap values in JavaScript context, and strips residual markup delimiters in text extraction. I confirmed that the code and test files changed; I did not run the tests or assess whether any earlier deployment was exposed.

Two follow-up changes upgrade patched documentation dependencies ([#18400](https://github.com/githubnext/gh-aw-cao/pull/18400)) and remove a vulnerable `braces` dependency ([#18419](https://github.com/githubnext/gh-aw-cao/pull/18419)).

## Dashboard experience

Several dashboard changes touch the files named in each pull request:

- Dashboard notifications are managed through a shared callout query and module under `dashboard/site/src/data/` ([#18506](https://github.com/githubnext/gh-aw-cao/pull/18506)).
- "Upgrade all" now handles partial inventory evidence ([#18450](https://github.com/githubnext/gh-aw-cao/pull/18450)), and update and upgrade pull requests gain CAO context and backlinks ([#18437](https://github.com/githubnext/gh-aw-cao/pull/18437)).
- Horizon selection and the compact picker layout were fixed ([#18398](https://github.com/githubnext/gh-aw-cao/pull/18398)), as were modal clicks that activated repository cards ([#18451](https://github.com/githubnext/gh-aw-cao/pull/18451)).
- An experimental model-routing analytics view built from unified sessions was added as a dashboard fragment ([#18475](https://github.com/githubnext/gh-aw-cao/pull/18475)).

I confirmed which files changed but did not review the rendered pages, so I can't describe how these look or how much they change daily use.

## Reliability and evidence ingestion

Experiment and eval artifact ingestion received fixes ([#18466](https://github.com/githubnext/gh-aw-cao/pull/18466), [#18465](https://github.com/githubnext/gh-aw-cao/pull/18465), [#18513](https://github.com/githubnext/gh-aw-cao/pull/18513)), and the ingestion documentation was updated ([#18486](https://github.com/githubnext/gh-aw-cao/pull/18486)). The release also upgrades gh-aw to prerelease v0.92.4 ([#18424](https://github.com/githubnext/gh-aw-cao/pull/18424)). I did not measure the effect of these changes on failure rates.

## What to do next

Because this is a pre-release, try it in a non-production control repository first. Read the [v0.1.21 release page](https://github.com/githubnext/gh-aw-cao/releases/tag/v0.1.21) and the [CAO Commands reference](https://github.com/githubnext/gh-aw-cao/blob/v0.1.21/docs/cao-cli.md). If you want to try `gh cao`, make sure Node.js 24 or later is available for the commands that rely on the runtime. If you run the dashboard server, review the static-serving fix before upgrading. The evidence I reviewed doesn't show changes to rollout defaults or live-mode authority.
