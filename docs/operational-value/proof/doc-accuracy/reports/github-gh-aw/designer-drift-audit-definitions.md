## How to read the timeline

- Observations begin at workflow adoption on `2026-06-04`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** Distinct explicitly written repository-local documentation references repaired from a nonexistent file to an existing file in a native parent/child transition. Separately: Count only explicit new invalid-shorthand-to-valid-ecosystem table mappings whose exact pair is independently specified in contemporaneous network reference documentation, or new safe-output mapping cells whose exact output name is both a workflow-schema property and a registered safe-output operation. Before source must lack that mapping. Require stable authoritative pair/key at both native parent and child. Mentioning a runtime operation absent from schema does not qualify.
- **Collection:** Replay hash-verified original Git objects with a deterministic local-reference oracle. Bounded selected cases are not exhaustive history.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Parent and child workflow source must both contain the designer synchronization goal and stale-reference audit.`; `Historical fixed-reference assessment authored before native outcome inspection; not ex-ante adoption measurement.`; `Outcome-informed retrospective authoring: frozen after source reading and bounded candidate PR prose describing repairs, before inspecting immutable native before/after contents or oracle results. Not blind, ex-ante, adopted at the historical workflow date, or backdated acceptance. Candidate prose is untrusted and does not establish native outcomes.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `designer-drift-audit-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
