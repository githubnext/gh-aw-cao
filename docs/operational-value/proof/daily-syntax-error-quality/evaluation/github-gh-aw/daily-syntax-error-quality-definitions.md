## How to read the timeline

- The measurement contract was activated on `2026-10-18`; this is not a workflow adoption date.
- No historical reference has been established.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Historical reference comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** Compiler errors that help developers actually correct syntax.

**Accepted outcome:** For native numeric-engine mutation opportunities, independently verify the exact file, line and engine-key or invalid-value token location, and an explicit repair restoring the native-accepted original. These are partial facets, not measured developer usability.

### Correct native diagnostic locations

- **What it tells you:** Correct native diagnostic locations. This is a `primary` measure.
- **Native measurement formula:** `100 * correctLocations / eligibleCount; null for absent, unsupported, incomplete or empty native evidence`
- **Unit:** `percent`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Verified explicit diagnostic repairs

- **What it tells you:** Verified explicit diagnostic repairs. This is a `diagnostic` measure.
- **Native measurement formula:** `100 * verifiedRepairs / eligibleCount; a unique native Did you mean or Example repair must restore the unchanged, native-accepted original`
- **Unit:** `percent`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** One distinct full document accepted by the pinned compiler, mutated only from a scalar built-in engine name to a numeric engine value, with original native validation JSON retained for both inputs.
- **Collection:** Offline, digest-checked original input and native gh aw compile --json outputs. Read the shared source archive once per batch. No API calls, code execution, inferred historical predicates, or reconstructed diagnostic prose.
- **Observation window:** 1 days, sampled every 1 days
- **Maturation delay:** 0 days
- **Filters:** `Exact repository ID 1036865607 and compiler revision c86377ec47b38f0b5af463277ee55d1d03d08da8.`; `Numeric-engine facet only; exactly one parse_error; no shared/redirect skip, ambiguous aliases, duplicate engine, multiline edits or inferred compiler results.`; `Native case completion in inclusive windowStart/exclusive windowEnd; never use acquisition timestamps as historical execution dates.`; `Actor independent. Agent scores, issue creation, closure, merges and editable tracking markers are not acceptance.`

The frozen goal, acceptance rule and formulas are applied to every observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `daily-syntax-error-quality-timeline.json` artifact.

## Important limitation

This report measures accepted repository outcomes against the stated goal. Contract activation is not an intervention or proof that an agent caused the outcomes; unavailable historical evidence supports no historical improvement claim.
