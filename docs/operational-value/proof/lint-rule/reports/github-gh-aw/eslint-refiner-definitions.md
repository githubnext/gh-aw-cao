## How to read the timeline

- Observations begin at workflow adoption on `2026-06-27`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** Improve existing ESLint factory rule precision, edge-case coverage, or actionable diagnostics using concrete diagnostic trends and feedback.

**Accepted outcome:** Distinct existing-rule refinements with independently demonstrated incorrect-before/correct-after diagnostic behavior on a real reported case plus a matched control; issue creation and tests authored are not correctness. Retrospective separately named partial facet: Compare the original isErrorListenerCall source before/after 105625bf3cecaa89a9a9dfc940e79fea25fe7634. Establish the exact added addListener alternative and independently verify Node EventEmitter.prototype.on === EventEmitter.prototype.addListener plus actual error delivery on own controls. This is one source-level standard-API compatibility correction, not a count of real false-positive diagnostics resolved; actual upstream rule execution, real-target prevalence and full rule precision remain null.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** One explicit source compatibility obligation; never substitute this for the original diagnostic-defect acceptance metric.
- **Collection:** Offline raw Git originals with commit-parent-tree-blob proofs; full production issue/PR inventory; independent own-code native oracle. No target code executes.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Existing eslint-factory rules and their actions/setup/js targets; Go rule changes are excluded.`; `Retrospective source- and outcome-informed partial instruments. These do not replace or backdate the frozen source-first full acceptance predicates.`; `Full source-first acceptance remains null; no zero is inferred from an empty selected interval.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `eslint-refiner-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
