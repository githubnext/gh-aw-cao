## How to read the timeline

- Observations begin at workflow adoption on `2026-01-07`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** Verify authenticated GitHub remote MCP compatibility independently of agent claims.

**Accepted outcome:** A protected raw-canary step, bound to its immutable executed workflow, completes initialize, initialized notification, ping, nonempty tool discovery including list_issues and a non-error list_issues JSON-RPC response.

### Verified raw MCP transport checks

- **What it tells you:** Verified raw MCP transport checks. This is a `primary` measure.
- **Native measurement formula:** `Count distinct assessed run-attempt identities whose source-bound protected raw step independently witnesses the complete frozen transport predicate; null without an assessed selected cohort.`
- **Unit:** `verified raw MCP transport checks`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** Three fixed pre-cutoff raw-canary attempts, not the lifetime run population
- **Collection:** Offline original GitHub responses: public repository identity, exact run/attempt/jobs, executed source/compiled scripts and protected raw-step runtime witnesses.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Original GitHub run, attempt jobs, exact-head editable and compiled workflow and protected raw-job log must be present and digest-verified.`; `The executed editable raw-canary script must exactly match the frozen revision's script, including official fixed endpoint, read-only header and repository-scoped list_issues payload.`; `The compiled workflow must contain that same script in the separate raw_mcp_canary job.`; `The uniquely matched completed raw step must contain actual runtime output in order, excluding printed shell source, ANSI-colored command echoes and unrelated job sections.`; `Initialize, initialized notification, ping, nonempty tool catalog including list_issues, list_issues non-error response and terminal handshake success must all be witnessed.`; `Reported protocol and tool count must be concrete; conflicting or malformed witnesses do not qualify.`; `Seven-day reporting is an explicit retrospective presentation choice, not a claim of ex-ante cadence or exhaustive weekly test coverage.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `github-remote-mcp-auth-test-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
