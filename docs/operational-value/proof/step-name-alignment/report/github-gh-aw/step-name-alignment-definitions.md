## How to read the timeline

- Observations begin at workflow adoption on `2026-01-13`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** Maintain consistent, accurate, descriptive compiled workflow step names under project terminology.

**Accepted outcome:** An immutable first-parent change replaces an explicit noncanonical project term with its glossary form, changes no other name wording, and preserves the parsed executable step and execution context. This verifies spelling only, not complete semantic naming quality.

### Observed glossary spelling repairs

- **What it tells you:** Observed glossary spelling repairs. This is a `primary` measure.
- **Native measurement formula:** `Count distinct uniquely matched compiled step occurrences whose only name change replaces one or more explicit glossary-backed variant spellings with canonical terms; each occurrence counts once. A partial subtotal is not the unknown complete-period total.`
- **Unit:** `step occurrences`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Observed frontmatter spelling repairs

- **What it tells you:** Observed frontmatter spelling repairs. This is a `diagnostic` measure.
- **Native measurement formula:** `Count the accepted native repair occurrences containing a front matter/front-matter to frontmatter replacement.`
- **Unit:** `step occurrences`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Observed agentic workflow term repairs

- **What it tells you:** Observed agentic workflow term repairs. This is a `diagnostic` measure.
- **Native measurement formula:** `Count the accepted native repair occurrences containing agent/agential workflow to agentic workflow replacement.`
- **Unit:** `step occurrences`
- **Goal:** Higher values are better.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** Statically named executable .github/workflows/**/*.lock.yml step occurrences changed on the frozen first-parent repository history, matched uniquely within a file/job by the complete parsed non-name execution context.
- **Collection:** Read the portable digest-checked immutable Git archive once per process, decode actual workflow YAML with pinned safe Psych, compare unique unchanged execution contexts and independent glossary headings. Reuse the native projections for all requested windows. No GitHub/API/database queries or execution of target code.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Exclude deleted/added/unmatched steps, changed executable context, ambiguous duplicate contexts and dynamic names from accepted repairs; retain their missing/unsupported scope.`; `Only exact canonical replacement of glossary-backed variants; style, generic clarity, casing preferences and arbitrary abbreviations are not lexical corrections.`; `Current source profile only. No claim that a missing object, issue, PR merge, editable marker or successful run proves improvement.`; `One repaired occurrence per file/job/unchanged context at its delivery commit, even when two term rules apply. Compiled occurrences are not deduplicated into presumed compiler templates.`; `Disjoint windows use inclusive start/exclusive end and committer time on retained first-parent history; later acquisition timestamps are provenance, not historical outcomes.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `step-name-alignment-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
