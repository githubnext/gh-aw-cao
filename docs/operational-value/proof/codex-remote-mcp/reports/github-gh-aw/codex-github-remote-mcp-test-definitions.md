## How to read the timeline

- Observations begin at workflow adoption on `2026-01-18`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** Verify that the Codex engine can use GitHub remote MCP to retrieve three open repository issues, or respect an explicitly returned integrity-policy content filter without bypass.

**Accepted outcome:** Count distinct source-bound Codex run-attempts with an independently captured, correlated native GitHub remote MCP list_issues invocation and non-error returned result. Direct gh/api/shell fallback, assistant prose, echoed examples, tool declarations and job success do not qualify.

### Verified native access

- **What it tells you:** Verified native access. This is a `primary` measure.
- **Native measurement formula:** `Count distinct source-bound attempts with independently correlated non-error native remote-MCP access; null without an assessed native case.`
- **Unit:** `verified access attempts`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

- **Unit:** `policy-filtered resources`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

- **What it tells you:** Upstream open issues. This is a `diagnostic` measure.

- **Unit:** `upstream issue identities`

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** All nine surviving pre-cutoff workflow run identities in a complete 100-item API page, not proof that each started an agent
- **Collection:** Offline exact provider-digest artifact, protected Codex stdout, matching native/normalized call IDs, independently captured official-backend gateway exchange and integrity-filter resource witnesses.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Count distinct source-bound Codex run-attempts with an independently captured, correlated native GitHub remote MCP list_issues invocation and non-error returned result. Direct gh/api/shell fallback, assistant prose, echoed examples, tool declarations and job success do not qualify.`; `Count distinct independently returned repository issue identities with concrete numbers, titles and OPEN/open state from an accepted native call requesting three issues from github/gh-aw. All three must be witnessed to establish the source-defined three-issue component. Filtered or missing contents remain unknown, not fabricated issue readbacks.`; `A concrete independently returned native integrity-policy filter with a concrete found count is an expected access-policy facet, never proof of issue-content readback or permission to bypass.`; `Preserve original public repository identity, run/attempt/job metadata, exact-head editable and compiled sources and protected provider/tool result originals. Verify execution identity, call correlation, host/path and timestamps where the native claim depends on them.`; `One accepted native-access observation per stable run-attempt identity. Native issue identities are deduplicated within their opportunity; repeated safety/capability checks are not fresh repository repairs.`; `Native access, returned issue bytes, policy-filter behavior, full goal completion and workflow-linked delivered contribution remain separate.`; `Absent, expired, skipped or incompatible original evidence is unknown, not zero accepted work or a proved failed tool.`; `No threshold, aggregate quality score, dollar value, cost, exclusive causation or deployment authority is inferred.`; `Current API state is acquisition-time evidence, not reconstructed historical issue state.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `codex-github-remote-mcp-test-timeline.json` artifact.

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
