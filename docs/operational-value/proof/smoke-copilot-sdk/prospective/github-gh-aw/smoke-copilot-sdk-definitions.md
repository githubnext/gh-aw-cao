## How to read the timeline

- Observations begin at workflow adoption on `2026-02-14`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** Verify SDK file writing/read-back and shell calculation capabilities.

**Accepted outcome:** Protected independent native file and process observations establish source-prescribed effects. Partial byte/operation facets, full task conjunction, required issue reporting and SDK contribution are separate.

### Verified native capability facets

- **What it tells you:** Verified native capability facets. This is a `primary` measure.
- **Native measurement formula:** `Count independently proven file-content creation, cat phrase-readback and exact bash 6*7 result facets delivered once in the period.`
- **Unit:** `operations`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

- **What it tells you:** New files with prescribed content. This is a `diagnostic` measure.

- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** Source-prescribed, independently identified run-specific file/readback/arithmetic challenge executions, regardless of actor.
- **Collection:** Offline digest-checked preserved source, complete related discovery, original provider artifact and protected attempt-log archives. One exact run/attempt native operation is admitted for its two independently demonstrated facets only.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Exact source/rule applicability and independently protected host receipt custody are required.`; `A newly observed file with required content is a narrower facet until current-date/time correctness is established.`; `No agent claims, caller trust flags, successful jobs or editable issue markers establish effects.`; `Count operation delivery once in inclusive-start/exclusive-end non-overlapping periods.`; `Validation examples never enter production collection or reports.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `smoke-copilot-sdk-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
