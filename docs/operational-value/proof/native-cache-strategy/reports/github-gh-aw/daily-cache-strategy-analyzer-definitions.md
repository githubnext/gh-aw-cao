## How to read the timeline

- Observations begin at workflow adoption on `2026-04-25`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** For workflows declaring cache-memory, independently demonstrate useful corrections to avoidable cache misses or misconfigured cache restoration over time.

**Accepted outcome:** A conditional compiled dependency-gate repair. Not observed detection success, cache publication, cache restoration, a cache-hit rate, avoided recomputation, cost saving or full workflow acceptance.

### Conditional cache dependency repairs

- **What it tells you:** Conditional cache dependency repairs. This is a `primary` measure.
- **Native measurement formula:** `Count distinct independently AST-verified compiler content-gate removals with an unchanged production cache consumer, once at actual delivery.`
- **Unit:** `compiler control-flow repairs`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** Content-gated detection dependencies of successful cache-memory agents
- **Collection:** Preserved public originals and complete selected Git commit/tree/blob custody; own native Go AST oracle; no target execution.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Original Git commit/tree/blob custody binds the actual first-parent before/after source transition.`; `A native Go AST proves that buildDetectionJob changes only by deleting its three content-gating temporaries and replacing BuildAnd(BuildAnd(alwaysFunc, agentNotSkipped), hasContent) with BuildAnd(alwaysFunc, agentNotSkipped). The remaining function body and signature are identical.`; `An unchanged real production workflow declares cache-memory. Its before/after compiled detection jobs differ only in the corresponding condition; the update_cache_memory job is byte-for-structure unchanged.`; `The original update_cache_memory job requires detection success and agent success. Under an agent-success, empty-output-types, no-patch case, the old detection condition necessarily skips that dependency. The replacement admits the dependency while preserving the downstream success requirements and cache-content guard.`; `Count the one compiler algorithm repair once, not every regenerated workflow, noop/boop label, test case or later report snapshot.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `daily-cache-strategy-analyzer-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
