## How to read the timeline

- Observations begin at workflow adoption on `2026-02-13`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** For temporary-ID smoke opportunities, resolve the six directed issue-body references into the correct real issues and establish the two requested parent-child relationships, independently joined to protected safe-output receipts.

**Accepted outcome:** A protected initial-attempt host receipt maps aw_test01, aw_test02 and aw_test03 to distinct stable GitHub issues; independent cutoff-valid bodies prove the six exact directed references, complete historical graph facts prove both children belong to that parent, and a protected comment receipt proves targeting of the mapped parent. Each known resolved reference counts independently of other missing dimensions.

### Verified resolved body references

- **What it tells you:** Verified resolved body references. This is a `primary` measure.
- **Native measurement formula:** `Count independently verified directed body-reference slots whose actual issue target equals the protected temporary-ID mapping.`
- **Unit:** `resolved references`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Verified child-parent graph links

- **What it tells you:** Verified child-parent graph links. This is a `diagnostic` measure.
- **Native measurement formula:** `Count source-required child-parent edges reconstructed at the observation cutoff from complete independent GitHub graph history and protected issue mapping.`
- **Unit:** `parent-child links`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Fully accepted temporary-ID triplets

- **What it tells you:** Fully accepted temporary-ID triplets. This is a `diagnostic` measure.
- **Native measurement formula:** `Count triplets with all six reference slots, both graph edges and a protected summary comment receipt targeting the mapped parent.`
- **Unit:** `accepted triplets`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** The six directed body references and two parent-child relationships per initial smoke execution; reruns do not create new work. Confirmed and unknown execution eligibility are separate; the eligible denominator is null wherever job history cannot establish it.
- **Collection:** Acquire the complete cutoff-bounded Actions inventory and every attempt, reuse the complete shared output-history discovery partitions, inspect all matching issue identities, acquire protected host job/log/artifact receipts, pin immutable workflow/runtime source, and independently project GitHub bodies and parent/sub-issue histories. Offline scoring never calls GitHub.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Only github/gh-aw, exact immutable reviewed workflow profiles and a protected safe_outputs host execution bind the mapping; editable body markers are discovery only.`; `Initial attempt only; reruns remain inventoried but do not inflate delivered references.`; `The six body slots are parent-to-child1, parent-to-child2, child1-to-parent, child1-to-child2, child2-to-parent and child2-to-child1.`; `Two native graph links are measured separately; a Related to footer or fallback comment is not a parent relationship.`; `Mutable bodies observed after cutoff require a platform last-edit/update timestamp no later than cutoff; otherwise their historical state is unknown.`; `Current graph edges require exhaustive historical add/remove facts to reconstruct the cutoff; current graph state alone is not backdated.`; `No proof from successful runs, jobs, agent summaries, evals, unresolved placeholders, issue existence, edited footer IDs or group-parent issues.`; `Empty populations and all-unknown populations score null, never zero. A known incorrect slot scores zero only for that assessed dimension.`; `3-8 versus original 4-8 format, agent engine, telemetry and report-format changes do not alter the fixed aw_test01/02/03 goal. Other source changes require review.`; `The source describes the third ID as eight characters, but all three actual fixtures have six suffix characters. No broad length-coverage claim is made.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `smoke-temporary-id-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
