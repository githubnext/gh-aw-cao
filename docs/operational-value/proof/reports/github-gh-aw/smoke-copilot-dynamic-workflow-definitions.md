## How to read the timeline

- Observations begin at workflow adoption on `2026-10-06`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** Maintain availability and actual completion of the packaged Copilot CLI dynamic workflow and its one native subagent.

**Accepted outcome:** Independent protected runtime evidence binds the immutable packaged extension to the named invocation, completed lifecycle and one correlated completed smoke-marker subagent; full acceptance additionally binds the exact five-field durable result to that invocation.

### Verified native invocations

- **What it tells you:** Verified packaged dynamic invocations. This is a `primary` measure.
- **Native measurement formula:** `Count independently source-bound completed native workflow invocations with exactly one correlated completed smoke-marker subagent; unknown attempts remain unknown.`
- **Unit:** `invocation proofs`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Exact result and invocation

- **What it tells you:** Exact durable-result acceptance. This is a `diagnostic` measure.
- **Native measurement formula:** `Count verified invocations whose correlated durable result equals all five exact source-defined fields.`
- **Unit:** `accepted invocations`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** Every initial execution attempt of the named workflow, including reusable calls selected by immutable caller configuration and native child-job identity; reruns are not new opportunities.
- **Collection:** Offline replay of digest-checked exhaustive frozen direct/caller Actions inventories, initial-attempt job receipts, artifact and log availability, immutable source/import/package closure and source history. Acquisition never executes fetched code.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `All potential reusable caller runs remain inventoried when actual branch selection cannot be reconstructed.`; `Agent-written results, editable issues, logs, fixture echoes and successful jobs alone do not establish native invocation.`; `Only an independent protected runtime receipt bound to the exact package/source profile establishes execution.`; `A completed native invocation is a partial outcome; the exact durable fixture result is a separate acceptance dimension.`; `No reconstructable independent pre-adoption execution evidence exists for this newly packaged fixture; this is not an invented zero baseline.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `smoke-copilot-dynamic-workflow-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
