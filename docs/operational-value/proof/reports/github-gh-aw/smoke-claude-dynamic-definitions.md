## How to read the timeline

- Observations begin at workflow adoption on `2026-10-06`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** Maintain packaged native Claude dynamic-workflow invocation, trusted hidden fixtures and argument propagation.

**Accepted outcome:** The protected host checks immutable packaged script/fixture equality, expected result/run ID, a native Workflow invocation and completion notification correlated to that invocation.

### Verified dynamic-workflow invocations

- **What it tells you:** Verified dynamic-workflow invocations. This is a `primary` measure.
- **Native measurement formula:** `Count initial-run native predicates established by every exact protected host assertion.`
- **Unit:** `invocation proofs`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Complete native proof count

- **What it tells you:** Complete native proof count. This is a `diagnostic` measure.
- **Native measurement formula:** `The same count, only when all eligible initial-run predicate assessments are known.`
- **Unit:** `invocation proofs`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** Initial execution attempts with immutable source-bound native host assertions; reruns do not create duplicate proof.
- **Collection:** Replay bounded, digest-checked Actions step receipts, immutable source/dependency identities and verified initial-attempt checkouts.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Only the exact reviewed protected job, its source-defined assertion steps and transitive local checker dependencies establish proof.`; `An overall successful run, job, agent reply, issue or unverified artifact does not establish the native predicate.`; `A failed assertion may reflect missing evidence, infrastructure or unmet preconditions; never infer a failed constituent behavior.`; `Known native proofs remain visible through incomplete historical coverage; complete totals require every eligible assessment.`; `The protected conjunction is not decomposed into guessed per-feature outcomes. Safe-output publication is outside this invocation facet.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `smoke-claude-dynamic-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
