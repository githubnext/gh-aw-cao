## How to read the timeline

- Observations begin at workflow adoption on `2026-01-29`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** For each activated initial workflow execution, demonstrate that each of the twelve source-required development tools is usable inside its agent container, by an actual native version/function invocation and valid native output.

**Accepted outcome:** A reviewed container-bound engine transport must independently correlate the source-required native version/function invocation with its successful completion and recognizable tool output. Equivalent native Java version flags and static absolute system paths are allowed. Agent prose, setup declarations, host-only version checks and mutable uploaded session files alone never establish execution.

### Observed native container tool proofs

- **What it tells you:** Observed native container tool proofs. This is a `primary` measure.
- **Native measurement formula:** `Count distinct (initial run, required tool) opportunities with an independent successful native invocation and valid output; preserve known proofs through gaps.`
- **Unit:** `tool proofs`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Complete native container tool proofs

- **What it tells you:** Complete native container tool proofs. This is a `diagnostic` measure.
- **Native measurement formula:** `The same native count only when all eligible tool assessments and eligibility are known.`
- **Unit:** `tool proofs`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** All retained runs created from adoption through the exclusive frozen cutoff, including every initial attempt. Reruns do not create duplicate opportunities. Skipped activation or skipped execution creates no tool opportunity; missing initial-attempt jobs leave eligibility unknown.
- **Collection:** Offline replay of complete retained initial-attempt inventory and digest-checked source-bound native host tool-execution receipts. Unknown history remains null.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Tool outcome predicates are stable since adoption; runtime pins, engine, container and transport changes are retained as separate profiles. No cross-profile trend is inferred.`; `Count independently established native tool proofs, preserving partial improvement. A complete total requires every eligible tool assessment. Known failures can establish zero; absent receipts cannot.`; `Version/function checks measure the source-required smoke facet, not compiler correctness, package restoration, arbitrary builds or every future invocation.`; `Source runtime pins are retained as context, not invented version-conformance requirements: the source's acceptance asks availability and valid output.`; `Imported Playwright title validation and token-telemetry checks are separate safeguards; they do not prove any of the twelve tools.`; `A successful run, comment or agent-printed version string is not a native execution receipt.`; `Deleted executions and expired logs/artifacts cannot be reconstructed from a present-day container replay.`; `Costs, exclusive causation, a keep threshold and full smoke acceptance are not measured.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `smoke-test-tools-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
