## How to read the timeline

- Observations begin at workflow adoption on `2025-11-11`.
- No comparable pre-adoption evidence is available. Complete adjacent post-adoption periods may still show recent change, but not change relative to adoption.
- Each dot is one immutable observation. Missing evidence is omitted, never treated as zero.
- Execution activity is diagnostic only. It does not prove repository value.
- Recent change compares the immediately preceding equal-duration period, not lifetime movement. Interval windows must abut without overlap; snapshot values compare cutoff states.
- Two observations show observed change, not a sustained trend, statistical anomaly or target attainment. Unknown coverage, gaps and provisional evidence make comparison unavailable.
- Adoption comparison is separate. Stable-but-bad outcomes are not healthy merely because their latest delta is zero; workload-mix changes can explain aggregate movement.

## What was measured

**Goal:** Understand codebase health and identify genuine quality improvement opportunities.

**Accepted outcome:** Partial native factual facet: both published direct workflow counts equal the actual immutable run-head regular-file inventory; independently compare the basename sets. This does not accept the source's health score or claim improved repository health.

### Bounded factual accuracy

- **What it tells you:** Workflow inventory count accuracy. This is a `primary` measure.
- **Native measurement formula:** `100 * independently accepted / independently assessed facts in this one explicitly bounded native facet; not full report accuracy`
- **Unit:** `percent`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Bounded assessment coverage

- **What it tells you:** Assessment coverage of eligible facet facts. This is a `diagnostic` measure.
- **Native measurement formula:** `100 * independently assessed / eligible literal native facts; no eligible facts is null`
- **Unit:** `percent`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

### Verified native facts

- **What it tells you:** Independently verified native facts. This is a `diagnostic` measure.
- **Native measurement formula:** `accepted independent native facts, not reports or generated items`
- **Unit:** `facts`
- **Goal:** Higher values are better.
- **Chart display:** The chart shows the native value directly on a metric-specific axis.

## Evidence rules

- **Repository:** `github/gh-aw`
- **Evidence population:** The two source-required direct workflow Markdown/lock count cells in the latest surviving marker-discovered report.
- **Collection:** Offline deterministic original-byte verification and native oracle; no model, Git, network, target execution, or current body/state backdating.
- **Observation window:** 7 days, sampled every 7 days
- **Maturation delay:** 0 days
- **Filters:** `Latest surviving pre-cutoff Discussion with this exact workflow marker in the already fully acquired inventory. One selected report per workflow; all other reports remain unassessed. No random, representative, blind or complete-lifetime claim.`; `Only this retained run-head source era; current worker assignment requirements are not backdated.`

The frozen definitions and formulas are applied to every post-adoption observation. The structured evidence, exact snapshots, provenance, units, and native values are recorded in the adjacent `daily-code-metrics-timeline.json` artifact.

## Important limitation

This report can show whether the intended outcome is attained after adoption. It cannot estimate change from pre-adoption conditions or attribute attainment to the workflow.
