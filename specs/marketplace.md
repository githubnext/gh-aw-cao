# CAO Campaign Package Marketplace

The marketplace is a read-only catalog projection. It does not install packages
or track installation state.

## Registry configuration

`control-plane.marketplace.registries` is an ordered list. Earlier registries
have higher precedence when two registries expose the same package coordinate.
CAO-created policies include the official catalog explicitly; deleting that
entry removes it.

Each registry declares `id`, `repository`, optional `path`, and `ref`. Optional
`api-url` scopes a registry to a GitHub Enterprise API endpoint. Authentication
is `none`, `pat`, or `github-app`. Authenticated entries contain only environment
secret names:

- `pat`: `secret`
- `github-app`: `app-id-secret`, `private-key-secret`, and
  `installation-id-secret`

Resolvers read those named secrets only in the trusted Activity or hosted
backend. Secret values and access tokens are never serialized.

## Package contract

Both backends return rows with the same safe fields:

`id`, `registry-id`, `registry-name`, `registry-precedence`, `name`,
`description`, `publisher`, `repository`, `path`, `ref`, `resolved-commit`,
`version`, `icon`, `artwork`, `contents`, `source`, and `add-command`.

Metadata is read from each package's gh-aw `aw.yml`. The command is generated by
the resolver from normalized package coordinates as
`./cao.sh add REPOSITORY[/PATH]@RESOLVED_COMMIT`.

Registry failures are isolated and reported as credential-free diagnostics.
